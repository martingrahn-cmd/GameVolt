From an empty folder to a living city

I had been vibe coding smaller games without being a programmer. Then I wanted to test something more extreme: how far can today's AI agents get when they are given a large project and allowed to work autonomously for days instead of minutes?

The brief was deliberately overambitious: build a Cities: Skylines-inspired 3D city builder in Three.js and Vite, with terrain, roads, zoning, buildings, traffic, public transport, economy, services, day and night, save and load, a living demo city and sensible performance.

A process, not just a prompt

The agent was not simply asked to implement a list of features. It was given a development loop:

Build → run → measure → capture → review → criticise → accept or reject → document → continue.

A change did not count as successful because it compiled. If an optimisation made the city look worse, it was rejected. If it broke deterministic save and restore, it was rolled back. If the verification tool measured the wrong thing, the tool itself had to be fixed and a new baseline established.

The critics were also prevented from inflating their own scores. A perfect score meant visually comparable with a modern AAA city builder. After more than 100 hours, parts of the project still sit near 6/10 or fail a review. That honesty is a feature of the experiment.

What the experiment produced

The current build contains a real 3D city simulation with roads, junctions, zoning, residential, office and mixed-use buildings. Traffic, service buildings, an economy and public transport all run inside the same simulation.

  • Bus lines, stops, scheduled buses, occupancy and operating costs
  • Day/night cycle, street lighting and illuminated buildings
  • Vegetation, water, bridges, terrain and changing weather
  • Automated camera, seed and time-of-day verification
  • Performance logs covering FPS, draw calls and triangle counts
  • Save and restore checks designed to catch lost determinism

The price of autonomy

The project began with the strongest model at high reasoning. It worked well enough to consume an entire 20× weekly compute allowance in roughly one day. That made model cost part of the engineering problem.

After checkpointing the project, a cheaper model continued the same implementation, screenshots, reviews, regression tests and performance work for several days without the expected collapse in quality. The more useful question became: what is the least expensive model that can reliably complete and verify this particular task?

Where the human still matters

AI can take measurable work surprisingly far. It can compare performance, repeat a seeded scene, inspect a screenshot and prove that a save restores correctly. It is much weaker when the answer lives in taste and feel.

Someone still has to say that a city looks wrong, an optimisation made the trees ugly, or a game is simply not fun. That person does not have to know how to implement a shader, a traffic model or a level-of-detail system. They do need a clear goal and the judgement to decide whether the result is actually good.

After 100+ hours, the most important test remains: is this something anyone actually wants to play?
